## 1. Overview

The webapp is a markdown viewer with an inline annotation system. Users can select text, add a comment in a popover, and see the resulting note rendered in a sidebar panel. Highlights are injected directly into the DOM via `<mark>` elements without re-rendering the markdown.

## 2. Data Types

**File:** `src/types.ts`

```typescript
export interface Annotation {
  id: string;           // UUID via crypto.randomUUID()
  text: string;         // The selected text content
  comment: string;      // The user-written comment
  range: SerializedRange;
}

export interface SerializedRange {
  startContainerPath: number[];  // Path from container root to start text node
  startOffset: number;           // Char offset within start node
  endContainerPath: number[];    // Path from container root to end text node
  endOffset: number;             // Char offset within end node
}
```

`SerializedRange` encodes DOM node positions as index paths (e.g., `[0, 2, 1]` = child 0 → child 2 → child 1) instead of live node references, enabling persistence and rehydration across renders.

## 3. State Management — `useAnnotations` Hook

| `cancelAnnotation()` | `AnnotationPopover` `onCancel` | Removes pending highlight, clears state |

## 4. Range Utilities

**File:** `src/utils/range-utils/range-utils.ts`

All DOM interaction is isolated here. No component manipulates DOM nodes directly.

### `getNodePath(node, root): number[]`
Walks from `node` up to `root`, recording each node's index within its parent's children. Returns `[]` if the node is not inside root.

### `resolveNodePath(path, root): Node | null`
Inverse of `getNodePath`. Walks down from `root` following child indices. Returns `null` on invalid paths.

### `serializeRange(range, container): SerializedRange`
Converts a live `Range` to a `SerializedRange` using `getNodePath` for both endpoints.

### `removePendingHighlight(container)`
Finds all `<mark data-annotation-id="pending">`, unwraps them (moves children to parent), then calls `normalize()` to merge split text nodes.

### `highlightRange(serialized, container, annotationId, className)`
1. Resolves both path ends back to DOM nodes via `resolveNodePath`
2. Reconstructs a live `Range`
3. Calls `getTextNodesInRange()` to enumerate all text nodes within the selection
4. Wraps each in a `<mark>` (processed in reverse order to preserve offsets)

### `wrapTextNode(node, start, end, annotationId, className)`
Handles partial wrapping — splits a text node if the selection starts or ends mid-node. Creates `<mark data-annotation-id="..." class="...">` around the target slice.

### `getTextNodesInRange(range, container)`
Uses `TreeWalker` to find text nodes within the range. Returns `{ node, start, end }[]` with correct per-node offsets.

## 8. AnnotationPopover Component

**File:** `src/components/AnnotationPopover/AnnotationPopover.tsx`

### Props

```typescript
interface AnnotationPopoverProps {
  position: { top: number; left: number };
  onSave: (comment: string) => void;
  onCancel: () => void;
}
```

### Behavior

- Positioned absolutely at `top/left` coordinates derived from the selection rect
- Auto-focuses the textarea on mount
- Keyboard shortcuts: `Escape` → cancel, `Ctrl/Cmd+Enter` → save
- Clicks outside the popover → cancel
- Save button disabled if comment is empty; `onSave` only called with non-empty content

## 11. Key Design Decisions

- **No re-render for highlights**: `<mark>` elements are injected imperatively into the rendered markdown DOM. This avoids re-parsing markdown on every annotation change.
- **Path-based range serialization**: Storing `number[]` paths instead of node references means ranges survive React re-renders and could be persisted to a backend.
- **Split text node handling**: `wrapTextNode` splits text nodes when the selection starts/ends mid-node, which is the correct approach for partial-word highlights but leaves the DOM in a modified state (managed via `normalize()` on cleanup).
- **Pending → committed two-phase model**: Green pending highlight gives immediate visual feedback before the comment is written. Cancellation cleanly reverts via `removePendingHighlight`.
- **Sidebar is stateless**: `AnnotationSidebar` receives a plain array prop; all logic lives in `useAnnotations`. Easy to test and extend.
